## Background: the model & method (from prev_paper.md)

- VPD decomposes each weight matrix into rank-one *subcomponents* $W_l \approx \sum_c \vec{U}^l_c (\vec{V}^l_c)^\top = U^l (V^l)^\top$, possibly overcomplete (more subcomponents than the matrix rank), to capture mechanisms in superposition.
- Subcomponents are trained to be parameter-faithful (sum to $\theta$), minimal, mechanistically faithful (robust to adversarially chosen ablations of unused subcomponents — the key difference from SPD's stochastic ablations), and simple.
- The paper builds attribution graphs between subcomponents ("circuits"), decomposes attention into cross-head subcomponents, and demonstrates model editing via parameter subcomponents.

## Checkpoint file formats

All checkpoints are plain PyTorch **state dicts** (named tensors), not pickled model objects — instantiate the architecture from `param-decomp` (or read tensors directly).

- Target checkpoints: flat state dict of `LlamaSimpleMLP` (`wte.weight`, `h.<l>.attn.{q,k,v,o}_proj.weight`, `h.<l>.mlp.{c_fc,down_proj}.weight`, `h.<l>.rms_{1,2}.weight`, ...).
- Decomposition checkpoints (`model_400000.pth`) contain three key groups:
  1. `target_model.*` — frozen copy of the target weights (self-contained file).
  2. `_components.<module>.{U,V}` — the subcomponent factors; subcomponent $c$ is rank-one $\vec V_c \vec U_c^\top$ (column $c$ of $V$, row $c$ of $U$); $VU$ reconstructs the weight matrix. Shapes e.g. SimpleStories `h-0-mlp-c_fc`: V (192,1152), U (1152,768).
  3. `ci_fn.*` — the causal-importance function: a small 4-block transformer (d=512) whose output head emits one importance value per subcomponent (7104 total for SimpleStories). Used to decide which subcomponents are active per token.

Architecture comparison between the two models: see `architecture_comparison.md`.

## SimpleStories token table

`simple-token-table/` holds `token_table.csv` (one row per token id), `sorted_token_table.csv` (same rows sorted by class → top_pos → freq desc), `README.md` (column documentation — read it before using the table), and the build script `token_table.py` (~5 min, needs spaCy `en_core_web_sm` — installed 2026-08-25; story cache in `simple-token-table/hide/data/`, gitignored). Classifies all 4,019 SimpleStories tokenizer tokens:

- `class` (mutually exclusive): `word` 2427 (standalone in the **majority** of occurrences: standalone_count/freq > 1/2) / `prefix` 762 (mostly the first piece of longer words — merge intermediates like `adventur`, plus minority-standalone words like `sleep`, `t`, `ben`) / `suffix` 798 (`##` continuations) / `punctuation` 20 / `digit` 10 / `special` 2.
- `freq` (corpus token count over 20k stories), `standalone_count` (occurrences as a complete word).
- POS distribution `pos_*` (fractions from spaCy on raw capitalized text; source: the dataset's `test` parquet shard) + `top_pos`. For prefix/suffix tokens the distribution is over words *containing* them; `example_words` lists the top 3 such words.
- `name_frac` = P(capitalized ∧ PROPN | mid-sentence standalone occurrence) — fraction of proper-name usage. `cap_frac` = capitalization alone. Both empty if < 3 mid-sentence occurrences. ~20 pure-name tokens (lily, ben, mia, ...), ~32 dual-use (mom 0.17, earth 0.37, keeper 0.42, fluff 0.83).
- Gotchas: spaCy-sm mis-tags lowercase "awe" as PROPN (why name_frac requires capitalization *and* PROPN); no published classification of this vocab exists (checked paper/repos/HF 2026-08-25). Tokenizer facts: WordPiece (greedy longest-match, `##` = continuation), lowercased, digits split individually, whitespace destroyed, no byte fallback (unknown chars → whole word = `[UNK]`); trained toward 4096 vocab but merges saturated at 4019.

## Analysis code

- `circles.py` (adapted from the user's "Abs in Sup" project): probes local geometry of the residual stream — output displacement along random directions, and Frobenius norms of Jacobians over a random 2-plane grid. Key conventions:
  - Layer coordinates in halves: 0 = post-embedding, 0.5 = after layer-1 attention, 1 = after layer 1, ..., n_layer = after last layer (final RMSNorm applied only when out_layer = n_layer).
  - `layers_fn(net, in_layer, out_layer, sequence=...)` returns the residual-stream map; `sequence=False` treats vectors as length-1 sequences, `sequence=True` runs real causal attention. `text_h0(net, tokens, in_layer)` gives the stream for a tokenized text (token ids as list[int] or 1-D tensor — e.g. `tokenizer.encode(text)` or a `pile_samples`/`simple_samples` row; no tokenizer argument).
  - Defaults everywhere: `sequence=True, vary='last'` (perturb + measure at the last token position only; output side is always the last position in sequence mode).
  - `vary='last'` Jacobians use KV-cached suffix differentiation (prefix keys/values cached without autodiff, jacfwd on a single position) — ~30x faster than naive autodiff and seq-len-independent; verified vs full-sequence jacrev on both models.
  - `text_change(net, tokens, ...)` / `text_jacobian(net, tokens, ...)` are token-input wrappers around the two plot functions.
  - Known corners, all ruled acceptable by the user (2026-08-24) — do not re-flag: `in_layer=n_layer` mixes pre-norm h0 with a post-norm map (irrelevant: only in_layer < out_layer is of interest); each call draws a fresh random plane (intentional); `sequence=True` default silently reinterprets a hand-built (B, d) vector batch as one sequence (acceptable: the main workflow is `text_jacobian`/`text_change`, where h0 is built internally and always consistent); stale demo comment/labels (user: don't worry about it).
- `load_simple_2l()`'s tokenizer is wrapped (`NoSpecialTokens`) so encode does NOT append [EOS]; the bare `load_tokenizer("simple_2l")` still does.

## Context-loss sub-project

`context-loss/` — how per-token loss depends on context length, both models (full writeup: `context-loss/report.md`). `compute.py` writes per-token (loss, within-doc EOS distance) arrays to gitignored `results/*.npz` (~10 min on local GPU, first run also fetches data); `plots.py` makes the figures + power-law fits. Key findings (2026-08-25): loss vs same-document context follows $L(n) \approx L_\infty + A\,n^{-\alpha}$ with $\alpha \approx 0.45$ (Pile, $L_\infty = 2.20$, still gaining at the full 512 window) vs $\alpha \approx 0.78$ (SimpleStories, saturates by $n \approx 100$); out-of-document context (across EOS) is worth ~nothing to either model; cold-open (first-token-of-doc) loss sits at the empirical entropy floor of document openings; loss vs *position in document* is non-monotone (formulaic openings, Pile entropy spike at positions ~4–6). Gotchas: HF datasets-server rate-limits after ~100 requests — the fetcher has backoff + partial caching; mean Pile doc length ≈ 1,450 tokens, so 86% of Pile tokens' documents start before their row (their `dist` is −1 = truncated context).

## Capability-analysis sub-project

`4L-capability-analasys/` — what the pile_4l model can/cannot do, measured per-token (full writeup: `4L-capability-analasys/report.md`). Pipeline: `compute.py` (400 cached Pile rows → 204,800 predictions: loss/rank/entropy/top-10 → gitignored `results/predictions.npz`) → `metrics.py` (accuracy by token class, copy-conditions, calibration, error anatomy) → `pos_check.py` (spaCy in-slot POS on errors) → `probes.py` (hand-built skill probes) → `sample_for_review.py` (340 stratified examples) → 8 parallel LLM judges (outputs in `review/agent_out/`) → `aggregate_reviews.py`. Key findings (2026-08-26): top-1 48.8%, ppl 15.1; copying dominates (85.8% top-1 when the (prev,target) bigram is in context vs 24.5% novel; pure-induction probe 84.8%); near-perfect calibration (ECE 0.007); 76% of errors judged plausible-or-equally-good, only 5% broken; errors preserve spacing 84% / case 90% / class 77%; grammar-agreement minimal pairs 13/14; facts are collocational (Barack→Obama 0.97) not relational (capital-of-France→Paris rank 494); arithmetic absent (2+2=→" -"); characteristic failure modes: safe-generic reflex, "grabby" copying (most salient antecedent, not correct one), template-without-grounding, list-item repetition over advancement. Gotchas: judges saw 60-token windows but the `bigram_seen` flag scans all 512; the high-loss tail is heavily contaminated by corpus noise/tokenization artifacts — don't equate loss with failure.

## Token-embeds sub-project

`token-embeds/` — token-embedding norm analyses, both models. `plot.py` → `embedding_norms.png`: norm histograms (+ pile zoom panel) with the mean init norm $0.02\sqrt{d}$ marked (init: wte ~ N(0, 0.02²); lm_head has `LLMC_SKIP_INIT` and is tied, so this is the only init) and top/bottom-10 norm tokens listed. `missing_tokens.py` → `missing_tokens.npy`: the 304 pile missing-token ids (see Standing instructions). `freq.py` → `freq.png`: scatter of corpus count vs norm (symlog x, count-0 strip) + equal-width-bin count histograms (integer positions 0–13 annotated, cutoffs marked) + count vs frequent/alive-PC1 projection (PC1 is a much cleaner frequency axis than norm: Spearman −0.63 pile / −0.81 simple); pile scatters colored by frequent/unfrequent/missing. `pca.py` → `pca.png` and `pca_interactive.py` → `pca_interactive_{pile_4l,simple_2l}.html` (zoomable): PCA spectrum (PCs always from frequent/alive tokens only) + per-group variance and mean projection along each PC (pile groups: frequent / unfrequent / missing; simple groups: alive / dead-seen / never-seen; sign convention frequent/alive-mean ≥ 0). Findings: pile near-isotropic (50%/90% var at 256/622 of 768 PCs), simple more structured (50/148 of 192); the last PC (simple) / last two PCs (pile) are effective **bias directions** — all-token shared offset with tiny alive variance (mean/std ≈ 8–12) — the no-bias network's constant for downstream layers to read. Key findings (2026-08-27): both models tied embeddings (verified in checkpoints; safetensors dedups the shared tensor — pile file has no `lm_head.weight` key). Norm tracks *specificity*, not raw frequency: highest norms = rare specialized fragments, lowest = frequent interchangeable tokens (names, numbers) at or below init norm; Spearman ρ(count, norm | count>0) = −0.27 (pile) / −0.51 (simple). `freq_direction.py` → `freq_direction.png` + `freq_direction_{pile_4l,simple_2l}.npy` (unit vectors): the best linear frequency direction — ridge regression (λ=0.01 by 5-fold CV) of log count on the raw frequent/alive embeddings; all reported correlations are cross-validated. Findings (2026-08-27): frequency is much better linearly encoded than PC1 suggests — CV Spearman +0.82 pile / +0.88 simple (vs PC1 0.64/0.78), CV Pearson(log count) 0.91 both; the direction is *distributed*, not PC1: cos(w, PC1) = 0.25/0.39, top-10 PCs give only 0.74/0.81, top-100 0.76/0.85, and the visually large w-coefficient on the last (bias) PC is a low-variance artifact (last-10 PCs alone: ρ ≈ 0.1; dropping them costs ~0.02). Residual scatter is partly Poisson count noise (pile counts from only 2.05M tokens), so these are lower bounds on decodability. Unfrequent tokens continue the trend monotonically out of the fit set; missing tokens sit far below it at the cone value. **For removing frequency from embeddings** (decision 2026-08-27): do NOT project out w — it has 57% of its mass in the bias PC(s) (ridge w ∝ Σ⁻¹Cov amplifies low-variance directions) and removing it leaves freq decodable at ρ ≈ 0.8; instead mean-center over alive tokens (kills the bias offset), then project out the covariance direction v_cov ∝ XᵀΔy (≈ PC1: cos 0.97/0.98) — this zeroes all linear covariance with log count, leaving only nonlinear remnants (|ρ| ≈ 0.3). Never-trained tokens don't decay to zero — the tied unembedding pushes them away from contexts (grad p_c·h̃ at every position, Adam-amplified) until weight decay balances: degenerate "rare-token cones" at norm ≈ 0.845 (pile — explains the 0.85 histogram spike) and ≈ 1.61 (simple, incl. [UNK], = the cone from simple-emb-clusters).

**Final-residual-stream activations (2026-08-28):** post-`ln_f` (pre-unembedding) vectors on training data — `hide/final_acts.py` (forward hook on `ln_f`; 200 cached Pile rows ×512 + first 360 cached stories ≈ 102k/100k positions; ~1 min local GPU) → gitignored `hide/cache/final_acts_{model}.npz` (acts + acts_pre [same positions just *before* ln_f] float32 + token_ids/row/pos).
